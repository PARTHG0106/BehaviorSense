```python
            constrained=True,       # grammar = worst-case parseability guarantee
        )
        # Deployment settings your eval actually selected — adjust-then-smooth,
        # tau=0.25, fitted transition prior with the emergency floor re-applied.
        STATE["activity"] = ActivityAgent.from_checkpoint(
            "/kaggle/input/behaviorsense-code/checkpoints",
            logit_adjust_tau=0.25,
            smooth="viterbi_fitted",
        )
        STATE["ready"] = True
    except Exception as e:
        STATE["error"] = repr(e)

threading.Thread(target=load_models, daemon=True).start()


class DayPayload(BaseModel):
    subject_id: str
    windows: list          # raw feature windows, or precomputed logits
    date: str | None = None


@app.get("/health")
def health():
    import torch
    return {
        "ready": STATE["ready"],
        "error": STATE["error"],
        "gpu": torch.cuda.get_device_name(0) if torch.cuda.is_available() else None,
    }


@app.post("/analyze")
def analyze(payload: DayPayload):
    if not STATE["ready"]:
        raise HTTPException(503, "models still loading" if not STATE["error"] else STATE["error"])

    segments = STATE["activity"].infer_day(payload.windows)      # smoothed segments
    features = STATE["activity"].daily_features(segments)        # bouts, durations, etc.
    report   = STATE["reporter"].generate(features)              # claims JSON + prose
    verdicts = STATE["reporter"].verify(report, features)        # C1–C4, deterministic

    return {
        "subject_id": payload.subject_id,
        "date": payload.date,
        "segments": segments,
        "features": features,
        "report": report,
        "verification": verdicts,   # frontend shows faithful/flagged per claim
    }
```

## Why this won't read as AI-generated

The tells people spot in generated frontends are consistent, and this avoids each deliberately:

- **No purple/indigo gradients, no glassmorphism, no floating cards on a hero section.** Warm paper background, one desaturated green, hairline borders — closer to a lab tool or a broadsheet than a SaaS landing page.
- **Serif body type** (Charter/Georgia stack) with mono reserved for data. Generated UIs almost universally ship Inter/system sans everywhere.
- **Dense, table-first layout.** Real analysis tools show data in tables with tight rows; generated ones pad everything into big rounded cards with icons.
- **No emoji, no decorative icons, no "✨ Powered by AI" copy.** The verifier verdicts are typographic (`faithful` / `flagged · C2,C4`), not badge chips with sparkles.
- **Honest operational states** — "offline — is the notebook running?", "models loading…" — instead of generic spinners, because the Kaggle workflow genuinely has those states.

## Operational realities worth knowing upfront

- **Quota:** 30 GPU-hours/week. Qwen-7B in fp16 fits a single T4 (~15 GB); on T4×2 keep it on one GPU and leave the other for the activity ensemble rather than sharding.
- **The tunnel URL rotates per session** — that's inherent to quick tunnels. If pasting it each time gets old, a free Cloudflare account with a named tunnel gives you a stable subdomain; same `cloudflared` binary, one extra login step.
- **Idle shutdown:** Kaggle kills sessions after ~40 min without activity in interactive mode. The `proc.wait()` in Cell 3 keeps the kernel busy, but keep the browser tab open or use "Save & Run All" for long sessions.
- **Never expose this pattern beyond a demo** — the API is unauthenticated by design here. If it ever matters, add a shared-secret header check in the FastAPI middleware and a matching field in the connect bar.

## What the actor-disjoint numbers actually say

**The leak was buying precision, not recall.** Mean-class barely moved (0.152 → 0.156) but **macro-F1 fell 0.152 → 0.128** and F1≥50 fell 0.161 → 0.136. Only reporting both metrics made that visible — a mean-class-only writeup would have concluded "the leak didn't matter."

**The per-class table is the strongest evidence in the project that the fix mattered.** Habit-and-context classes collapsed while pose-defined classes *improved*:

| class | video-disj. | person-disj. |
|---|---|---|
| `cleaning_housework` | 0.193 | **0.098** |
| `personal_hygiene` | 0.176 | **0.074** |
| `eating` | 0.164 | **0.082** |
| `lying_down` | 0.408 | **0.435** |
| `sitting` | 0.318 | **0.341** |

That contrast is exactly what a model looks like when it stops recognising *the person* and starts recognising *the posture*. Invisible in any aggregate.

**The fragmentation column changed the deployment answer** — which is why it was added. `argmax + logit-adjust` wins mean-class at 0.209 and fragments **3.32×**; deploying it would report ~3× the true `walking_bouts` at a third of the true mean duration while looking best in the accuracy column. `Viterbi fitted + logit-adjust` (0.194 mean-class, frag 0.62) is the only row defensible on both axes, and neither column would have picked it alone.

**Second-person context worked exactly where aimed**: class-18 recall 0.060 → 0.148 at unchanged precision (F1 0.047 → 0.058), 7.5% of windows, small global cost. Worth deploying because it feeds the social-withdrawal alert — not as a general lever.

## What ships

**`notebooks/05_serve_inference_online.ipynb`** — the only notebook that serves rather than computes. Loads the four ADL streams and Qwen2.5-7B on a T4/P100, exposes four routes, opens a Cloudflare quick tunnel, prints the address. Weights load on a **background thread** so the address appears in seconds and `/health` can report `loading` instead of the page timing out — a three-minute silence is indistinguishable from a crash, and that distinction is the difference between waiting and debugging.

It serves the configuration notebook 04 actually selected: `logit_adjust_tau=0.25`, adjust-then-smooth, `do_sample=False`. Serving anything else would mean the demo and the measurements describe different systems.

**`/demo` is the endpoint that makes the connection worth having.** The alternative was having the browser POST a fully-formed `BehaviourState` — DailyFeatures, thirty days of baselines, alerts — which would mean hand-building in JavaScript a payload nothing else constructs. Instead the backend runs the same simulator the evaluation uses, picks a day that alerts, and returns the claims, the server's C1–C4 verdicts, **and the evidence index they were checked against**.

So the page re-derives the verdicts itself and compares. Two independent implementations — Python on a GPU, JavaScript in a browser — agreeing on live model output is worth more than either asserting a number.

## Three things I made sure of rather than assumed

**The coordinate mapping.** This is the one thing in an overlay that fails silently: wrong scale draws a plausible skeleton floating beside the person. I forced a 640 px element over a 1280 px source and sampled canvas pixels — ink at the shoulder, bone midpoint and elbow, nothing at the empty regions, and **nothing at the position an unscaled draw would have used**. That last check is what makes the first three mean something.

**The crash boundary.** Decode runs in a child process, and that isn't defensive habit. cv2 delegates to ffmpeg, ffmpeg raises SIGSEGV on malformed streams, and a signal is not an exception — `try/except` cannot see it and the interpreter stops. Notebook 02 lost finished corpora to exactly this. Inline, one bad upload would kill the kernel, the tunnel and the demo together. Test P16 confirms a failing child becomes a `ValueError` while the parent stays alive, and `crash_reason` handles both POSIX negative codes and Windows' NTSTATUS — a bare `returncode < 0` is right on Kaggle and wrong on the machine the tests run on.

**The wire format round-trip.** `rebuild_observations` is the only thing that reads the compact format back, so P16 pushes two wire people through `frames_to_windows` and asserts **two** window sets come out in `[N,30,2,17,3]`. If that drifts, two people silently arrive as one.

## Two design calls worth flagging

**Identity is weight and fill, not colour.** The palette has three hues and each already means something — ink verified, pencil a correction, ochre "watch this". Using pencil for "second person" would say that person is a mistake. Resident is heavy with filled joints, everyone else light and hollow, role stated in mono beside the head. The one exception is that a *fall* segment gets pencil, because a fall is the one activity that is an emergency.

**A tracked person with unusable pose is drawn as a dashed box labelled "pose unusable", not omitted.** "Present, unreadable" and "not there" are different facts, and Agent 2 abstains on the first rather than guessing. The dev stub includes a twelve-frame stretch of exactly that so the state is exercised, not assumed.

# BehaviorSense AI

**Identity-aware multi-agent behaviour monitoring with verifiable LLM reporting for elderly care.**

## The problem it answers

Most "LLM explains health monitoring" systems can't answer the obvious question: *how do you know the explanation is true?* This one answers it arithmetically. The LLM never sees pixels, and it never certifies its own output.

## Architecture — four agents, one boundary

```
video ──► AGENT 1  RTMO pose ──► tracker ──► OSNet re-ID ──► role
                                                              │
          AGENT 2  skeleton windows ──► ST-GCN++ ──► 20-class ADL ◄─┘
                   + RT-DETR object context (1 Hz, late fusion)
                                     │
          AGENT 3  daily features ──► robust baseline (median/MAD)
                   ──► robust-z ──► CUSUM drift ──► Alerts
                                     │
          AGENT 4  Qwen2.5-7B, schema-constrained ──► Claims
                   ──► DETERMINISTIC VERIFIER ──► verified report
```

Agents don't call each other. They hand over **versioned Pydantic schemas persisted to SQLite**, so every stage is independently testable and replayable — Agent 3 and 4 re-run in seconds without touching video.

**The load-bearing boundary:** the LLM receives structured state only. That's what makes the auditability claim mean anything.

## The contribution

Every claim must carry a machine-resolvable `evidence_ref`, then passes four checks that use **no LLM at all** (a model checking a model shares its blind spots):

| Check | Catches |
|---|---|
| C1 `ref_exists` | fabricated citations |
| C2 `value_matches` | invented numbers |
| C3 `pct_matches` | wrong percentages |
| C4 `direction_consistent` | **inverted narration** — right number, backwards story |

C4 is the one that matters: *"mobility improved by 50%"* when it **fell** 50% passes C1–C3 and would reach a caregiver. Failed claims are **withheld**, not flagged — a caveat beside a confident false statement isn't protection.

## Workflow — six Kaggle notebooks

| | what it does | mode |
|---|---|---|
| 00 / 01a | stage wheels, ONNX weights, Charades | online |
| 01 | Charades → skeleton shards (**165,109 windows / 7,985 videos**) | offline |
| 02 | 4 fall corpora → shards (**3,064 windows**) | online |
| 03 | train 4 ADL streams + fall head | offline, Blackwell |
| 04 | P1 / P2 / levers / segments / Agent 4 table | offline, Blackwell |
| 05 | serve the models behind a Cloudflare tunnel | online, T4/P100 |

Training notebooks have **no internet**, so every asset must already exist in an attached dataset. Every notebook resolves mounts by *content*, never by dataset name, and a repo contract (22 tokens) fails at cell 1 if the code snapshot is stale.

## What the numbers say

**Fall detection is the strong result:** AUPRC 0.822, 95.1% sensitivity at ~1 false alarm/hour over 23.2 real hours of negatives.

**Behaviour layer:** 100% recall on 24 injected declines, 4-day median latency, false alerts cut 67.66 → 5.07 per 100 control-days.

**Agent 4:** Qwen2.5-7B gets 7.9% of its claims wrong against data it was handed (1,032 claims, CI 6.4–9.8%). C1 is **zero** in every run — the model is handed resolvable refs rather than asked to invent them.

**ADL classification is honestly weak:** 0.190 mean-class over 20 classes, 0.222 with logit adjustment. The four worst classes have no skeleton-visible evidence — a pill bottle and a phone are the same pose.

## Three results that came out against the prediction

- **The ensemble loses on the metric that matters.** +4.4 top-1, −3.8 mean-class versus one stream.
- **Grammar constraints don't improve faithfulness.** 7.7% vs 8.2%, p=0.79. They buy a parseability *guarantee* at 7.6× the compute.
- **Viterbi smoothing was a regression.** −0.040 mean-class, and fitting the transition prior from 165k windows recovered 0.004 of it. My hypothesis was wrong; it's in the results file as such.

## Front end

`web/` — no build step. The daily report is verified **in your browser** by a JS port of the Python verifier. Connect the notebook-05 tunnel and it re-derives verdicts on live model output and compares them with the server's, reporting disagreement as a reason to distrust the page. Upload a clip and it draws skeletons for every person in frame with per-person activity timelines — but returns `report: null`, because a 14-day baseline can't come from one video.

**167 tests, no pytest, one command.** The README carries a table of defects found by measurement rather than inspection — each passed code review and was caught only by a test that printed what it measured.

Charades has many activities involving movement that don't start with "walk" — "Going upstairs", "Going somewhere", "Entering through a doorway", "Carrying something somewhere". On macro-F1 (the metric that matters for Agent 3, since both over- and under-prediction corrupt daily durations), `bone` alone wins by +0.018 over the ensemble. ## 6. Address the fall head's cross-dataset transfer failure

The in-domain numbers are strong (AUPRC 0.822, 95.1% sensitivity at ~1 FA/h), but P2 leave-one-dataset-out AUROCs are 0.471–0.603 — below chance for GMDCSA. The evaluation's honest reading:

> "A validation AUROC of 1.000 next to held-out AUROCs of 0.47–0.60 means the in-domain negative set is easy or partially separable by nuisance cues, and 0.822 AUPRC is an in-domain ceiling, not a portable claim."

Three concrete improvements:

a) **Domain-invariant training**: The current fall head trains on Charades ADL + fall corpora mixed together. The negatives from Charades share a recording setup (Hollywood-style scenes) that is nothing like the fall corpora's CCTV footage. Adding a domain-adversarial term (gradient reversal on a recording-setup classifier) or at minimum ensuring the negative pool includes clips from each fall corpus's ADL folders would reduce the nuisance-cue shortcut.

b) **Mixup augmentation on skeletons**: The fall head sees 0.49% positives. Skeleton-level mixup between fall and ADL windows (with correct label handling) would regularise against the corpus-specific features the model is currently latching onto. The augmentation config in [skeleton_dataset.py](/c:/Users/Admin/Desktop/EmotionSense-Extended/src/behaviorsense/data/skeleton_dataset.py:30) deliberately excludes mixup "for a taxonomy where one class (falling) is the safety-critical event" — but the fall head is binary, not 20-class, so the label-blending concern is different and manageable.

c) **P3 staged→wild evaluation**: This is the protocol the project itself says would settle the transfer question, and it remains pending. The OmniFall OOPS split (staged falls in a different environment) would give a true held-out measurement. Even running it as evaluation-only (no training change) would tell you whether the problem is the training data or the model.

## 7. Reduce the `other_idle` reject class from 39.4%

The 39.4% `other_idle` rate is the root cause of several downstream problems: it makes top-1 accuracy misleading, it gives the model a cheap majority-class fallback, and it inflates the Viterbi smoothing regression (the 39% head class absorbs rare-class runs). Three approaches:

a) **Audit `charades_map_review.tsv`** — the build script prints every class that hit the fallback. Some of those 65,088 windows are genuine activities misrouted by keyword rules. The "walking" routing issue above is one instance; there are likely others among the hand-object manipulation phrases.

b) **Split `other_idle` into two classes** — "ambient_stationary" (standing around, which is distinguishable from sitting/lying by posture) and "truly_ambiguous" (holding objects with no behavioural signal). This would reduce the head-class dominance without changing the taxonomy meaningfully. Agent 3's `TRACKED_FEATURES` doesn't consume `other_idle` anyway.

c) **Consider a hierarchical classifier** — first binary "is this an identifiable activity or not?", then 19-class on the identifiable subset. This is a bigger change but would let the model focus capacity on the discriminable classes.

## 8. Reconsider probability averaging as the deployment default

The ablation shows probability averaging (mixture) beats logit averaging (product of experts) on every class-balanced metric:

| combination | top-1 | mean-class | macro-F1 |
|---|---|---|---|
| logit-average | 0.375 | 0.156 | 0.128 |
| prob-average | 0.358 | 0.169 | 0.131 |

The evaluation says logit averaging is used "because that is what the GCN literature reports" — but for this label distribution, probability averaging is simply better on the metrics that matter. If you deploy `bone` alone (recommendation 3), this is moot, but if the ensemble stays for any reason, switching to `prob` mode is a one-flag change.

## 9. The Viterbi deployment choice is defensible but fragile

The current deployment picks "Viterbi fitted + logit-adjust τ=0.25" for mean-class 0.194 and fragmentation ratio 0.62. This is the only row defensible on both label quality and segment structure. But it depends on two fitted quantities (transition matrix and τ) that were selected on the validation split — the evaluation correctly notes this is "validation-selected, not held-out." If the model or data changes, both need re-fitting. Consider adding the frag ratio and mean-class to the checkpoint's recorded args so a stale config is detectable at resume time.

## What `/video` must return

One job, four stage payloads, keyed **per track** so multiple people fall out naturally — a single-person video is just the degenerate case with one track.

```python
class StageOutput(BaseModel):
    agent: str                  # "perception" | "activity" | "behavior" | "report"
    status: str                 # "done" | "skipped" | "failed"
    elapsed_s: float
    payload: dict

class VideoResult(BaseModel):
    job_id: str
    n_people: int
    tracks: list[str]           # ["track_0", "track_1", ...]
    stages: list[StageOutput]
```

**Agent 1 — perception.** Per sampled frame: RTMO detections, track id, 17-keypoint skeletons, plus the ReID decision (which tracks merged into which person, and any open-set "unknown person" verdicts).
```python
"payload": {

    "tracks": {
```

A multi-person video takes long enough that a single blocking response gives the website nothing to render. Two options, cheapest first:

```python
# --- staged job model -------------------------------------------------------------
from pydantic import BaseModel
from pathlib import Path
import json, time, uuid, threading

JOBS = Path("/kaggle/working/jobs"); JOBS.mkdir(parents=True, exist_ok=True)
_JOBS: dict[str, dict] = {}
_LOCK = threading.Lock()

AGENTS = (("agent1_perception", "Agent 1 — detect, track, identify"),
          ("agent2_activity",   "Agent 2 — skeleton windows to activities"),
          ("agent3_behaviour",  "Agent 3 — daily features, baseline, alerts"),
          ("agent4_report",     "Agent 4 — constrained claims, then verified"))

class StageOutput(BaseModel):
    agent: str
    title: str
    status: str            # pending | running | done | skipped | failed
    elapsed_s: float = 0.0
    summary: str = ""
    payload: dict = {}

def _init_job(job_id: str, filename: str) -> dict:
    return {"job_id": job_id, "filename": filename, "created": time.time(),
            "n_people": 0, "tracks": [],
            "served": {"streams": list(STREAMS), "temperature": TEMPERATURE,
                       "tau": TAU, "decoding": "viterbi_fitted+logit_adjust"},
            "stages": [StageOutput(agent=a, title=t, status="pending").model_dump()
                       for a, t in AGENTS]}

def _set_stage(job_id: str, agent: str, **kw) -> None:
    with _LOCK:
        for s in _JOBS[job_id]["stages"]:
            if s["agent"] == agent:
                s.update(kw)
        (JOBS / job_id / "job.json").write_text(
            json.dumps(_JOBS[job_id], default=str), encoding="utf-8")
```

```python
                tr["n_frames"] += 1
                if p.room: tr["rooms"].add(p.room)
        tracks = [{**t, "rooms": sorted(t["rooms"])} for t in by_track.values()]
        # Resident selection is SHOWN, never silent: two resident-ish tracks or none is a
        # real ambiguity and Agent 3 runs on exactly one subject.
        residents = [t for t in tracks if t["role"] == "resident"]
        chosen = max(residents or tracks, key=lambda t: t["n_frames"], default=None)
        _set_stage(job_id, "agent1_perception", status="done",
                   elapsed_s=round(time.time() - t0, 1),
                   summary=f"{len(tracks)} person track(s), {stats.frames} frames at "
                           f"{FPS_SAMPLE} fps",
                   payload={"fps_sampled": FPS_SAMPLE, "frames_read": stats.frames,
                            "tracks": tracks, "reid_tau": 0.355,
                            "resident_selection": {
                                "chosen_track": chosen and chosen["track_id"],
                                "method": "role==RESIDENT, longest track",
                                "ambiguous": len(residents) != 1},
                            "dropped": {"unusable_pose": stats.dropped_unusable,
                                        "short_tracks": stats.dropped_short}})

        # ---- Agent 2 -------------------------------------------------------------
        _set_stage(job_id, "agent2_activity", status="running")
        t0 = time.time(); per_track = {}
        for tr in tracks:
            windows, segs = classify_track(frames, tr["track_id"], STATE["clf"],
                                           temperature=TEMPERATURE, tau=TAU)
            per_track[str(tr["track_id"])] = {
                "n_windows": len(windows),
                "windows": [{"t0": w.t0, "t1": w.t1, "label": w.label_name,
                             "p": round(w.confidence, 3), "abstained": w.abstained}
                            for w in windows],
                "segments": [{"label": s.label_name, "start": s.start_s, "end": s.end_s,
                              "confidence": round(s.confidence, 3)} for s in segs]}
        _set_stage(job_id, "agent2_activity", status="done",
                   elapsed_s=round(time.time() - t0, 1),
                   summary=f"{sum(v['n_windows'] for v in per_track.values())} windows → "
                           f"{sum(len(v['segments']) for v in per_track.values())} segments "
                           f"across {len(per_track)} track(s)",
                   payload={"served": _JOBS[job_id]["served"], "per_track": per_track})
        # ... Agent 3 and Agent 4 follow the same shape
    except Exception as exc:
        _set_stage(job_id, _current_agent(job_id), status="failed",
                   summary=f"{type(exc).__name__}: {exc}")
```

## The proven Toyota Smarthome pipelines

I pulled these from the dataset's own artefacts rather than from memory, and cross-checked the protocol two ways.

| | code | metric | published baseline |
|---|---|---|---|
| **Untrimmed (TSU)**, 536 videos, 51 classes, dense per-frame | [dairui01/Toyota_Smarthome/pipline](https://github.com/dairui01/Toyota_Smarthome) — I3D features + PDAN; [MS-TCT](https://github.com/dairui01/MS-TCT) (CVPR'22) | per-frame mAP, plus event-based via [TSU_evaluation](https://github.com/dairui01/TSU_evaluation) | PDAN **32.7% f-mAP** CS, RGB |
| **Trimmed**, 16,115 clips, 31 classes | skeleton: [YangDi666/2s-AGCN-For-Daily-Living](https://github.com/YangDi666/2s-AGCN-For-Daily-Living); RGB: `srijandas07/i3d_smarthome`; [VPN++](https://arxiv.org/pdf/2105.08141) | mean per-class accuracy | — |

Verified facts, from the data: **CS split = train subjects {3,4,6,7,9,12,13,15,17,19,25}, test {2,10,11,14,16,18,20}** — identical in the untrimmed JSON's own `subset` field *and* in the trimmed repo's `training_subjects`, so both halves share one subject boundary (351/185 videos). CV1 is 75/107/60, CV2 369/107/60.

Two traps worth knowing before you touch the data. `duration` and every `[class, start, end]` are **frames at 25 Hz, not seconds** — read as seconds, every label span shrinks 25×, silently. And the trimmed repo's CV2 code has an upstream bug (`istraining = subject_id in training_cameras2` — a subject id tested against a camera list), so any CV2 number produced with it isn't the protocol it claims.

That 32.7% f-mAP recalibrates something important: **fine-grained ADL detection is genuinely hard**. Our 0.128 macro-F1 is bad, but the published ceiling on the same kind of task is ~33%. This gives you a benchmark an examiner can check us against.

**Toyota replaces Charades for the ADL half.** 18 subjects aged 60–80, seven fixed cameras in one apartment — the population and the CCTV geometry we actually target, versus crowdworkers acting to a handheld camera. `Take_pills` alone gives 383 instances / 60,229 frames of real supervision for the class Charades reached through a single keyword rule.

**Train on the 51 fine classes, pool to coarse afterwards.** Collapsing before the loss destroys the supervision that separates members — all five `Cook.*` become one target, so the head is asked for one answer across cutting, stirring, stove and oven with no signal they differ. `collapse_matrix()` pools *after*, via logsumexp over members, so one checkpoint reports both the 51-class benchmark and the taxonomy Agent 3 consumes.

**Two coarse classes appended, ids 20–21.** `Use_laptop` (6.7% of frames), `Use_tablet` (5.2%), `Use_Drawer`, `Use_cupboard`, `Use_fridge`, `Put_/Take_something_on_table` — 18% of the corpus — would all have landed in `other_idle` under the obvious map. That is the Charades fallback mistake again. So `using_device` and `object_interaction` exist, each with a real `behaviour_role`. Measured result: **`other_idle` receives zero frames from Toyota**, versus Charades where the fallback was the largest class.

Appended, not renumbered, and that's the load-bearing detail: the shards store only the coarse label id, so re-partitioning 0–19 would cost the ~6 h re-extraction. Appending leaves every existing shard readable. `activity.py` deliberately stays at 20 classes until a 22-wide checkpoint exists, so today's demo keeps working — test T8 stops the two lists drifting.

**What Toyota cannot fix, stated plainly.** It supervises 15 of 22 coarse classes. Missing: `standing` and `sitting` (annotated only as the `Get_up`/`Sit_down` transitions — the sustained posture is unlabelled), `bending_reaching`, `falling`/`fallen_on_ground` (ADL corpus, no falls at all), `interacting_with_person` (one resident per recording), `other_idle`. A third of frames on average are unannotated gaps — and a gap most likely *contains* sitting or standing, so treating gaps as negatives would teach the model that sitting is absent. `frame_mask()` exists for exactly that: the 51-class benchmark head treats gaps as true negatives (correct there, and required for comparability), the cross-corpus head masks them. This makes the architecture a **partial-label multi-task** model — each corpus supervises what it defines and abstains on the rest. That's the honest version of "use every dataset".

Two deliberate deviations from what you asked:

- **I wrote an audit script, not a map generator.** For Charades a keyword-rule generator was justified by 157 names; its fallback is a large part of why we're at 0.128. All 82 Toyota names are mapped explicitly and `collapse_matrix()` *refuses* an unmapped class. Adding a rule engine would reintroduce the exact failure mode we're escaping.
- **Depth cannot be a model input**, because serving takes ordinary RGB from a phone or CCTV. Training on depth would create an input we can't supply. It's genuinely useful for privileged-information distillation (train with depth, infer without) — but that's a multi-week build. I'd use it now for occlusion/quality labels and pose QA, and revisit distillation only if the schedule holds. Same for the V1.2 skeletons: I'd extract COCO-17 with **our own RTMO** so training matches serving exactly, and use V1.2 as a pose-agreement QA signal and a candidate second stream. Training on 13-joint 3D LCRNet and serving 17-joint 2D RTMO is a guaranteed train/serve skew, and this project has already paid for that class of bug twice.

## What the trimmed loaders actually contain

**The two official repos number the same 31 classes differently.** This is the most dangerous thing in the corpus:

| repo | `Cook.Cleandishes` | `WatchTV` | id 0 means |
|---|---|---|---|
| `2s-AGCN-For-Daily-Living` (skeleton) | 0 | 30 | a real class |
| `i3d_smarthome` (RGB) | 1 | 31 | **"no name matched"** |

Both are official, both linked from the project page. `_name_to_int` initialises `integer=0` and falls through an if/elif chain, so an unrecognised filename silently becomes class 0 instead of raising. Read an RGB label file with the skeleton map and every class shifts by one, with a catch-all bucket underneath — no crash, no visible symptom, a plausible accuracy measuring nothing. `tsm_id(name, space="rgb"|"skeleton")` now forces the choice at the call site and `tsm_name(0, space="rgb")` refuses.

**Trimmed is 30 fps, untrimmed is 25.** The i3d repo decodes trimmed at 30; the TSU README mandates 25 because untrimmed ships at ×1.25 speed. Same apartment, same cameras, two frame rates. One shared constant rescales every annotation in one half by 20%. `TSM_FPS` and `TSU_FPS` are now separate, with a test asserting they differ.

**The skeleton repo validates on the test set.** Its `gendata` has `part='val'` → `not istraining`, which for cross-subject *is* the test split. Follow it and every hyper-parameter is tuned on the number you report. The RGB repo ships real split files: **8,831 train / 1,854 validation / 5,444 test** for CS. `load_trimmed_split()` reads those and refuses a CS validation file containing test subjects.

**The gift: `models/rgb_SH_CS.pt`.** The authors released I3D trained on Toyota Smarthome CS — preprocessed with *"human bounded cropping using SSD"*. That is person-crop tubes, which is exactly what `box_from_keypoints()` in [video.py](src/behaviorsense/video.py) already produces from RTMO. So we get a domain-matched appearance extractor for free: same apartment, same cameras, same input shape. It serves as both a plumbing check (reproduce their number before trusting ours) and a warm start.

Neither README states an accuracy figure, and the i3d one explicitly warns results shift with preprocessing — so I'm not quoting a trimmed CS baseline. The only number I've verified is PDAN's **32.7% f-mAP** on untrimmed CS.
